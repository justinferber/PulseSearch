## What was implemented

M12 adds a working, admission-aware research path:

`question -> query plan -> provider leads -> exact source-policy match -> robots + SSRF-safe fetch -> extracted evidence -> deduplicated candidates -> cited answer`

- `pulse_search_broad_r3a3g/m12_research.py`: query planning, SearXNG discovery, exact approved-source retrieval, VisitBritain list extraction, entity deduplication, factual/date answers, comparison extraction, navigation fallback, conflict reporting, follow-up sessions and shortfall reporting.
- `pulse_search_broad_r3a3g/m12_feedback.py`: privacy-conscious reviewed feedback. Stores a hashed query shape, source domain, verdict and reviewer; never stores the raw question. Produces an advisory ranking proposal with `automatic_apply: false`.
- `config/m12_sources.json`: ten exact, approved demonstration URLs with rights, approval reference, authority, jurisdiction, language and topic metadata. This is a controlled demonstration policy, not a general crawl licence or production approval.
- `pulse_search_broad_r3a3g/api.py`: authenticated `POST /v1/research` behind the new `research:read` scope. Existing endpoints keep their scopes and behaviour. `/v1/capabilities` reports whether dynamic research is configured.
- `pulse_search_broad_r3a3g/client.py`: PUKE-side `PulseSearchClient.research()` preserving candidates, claims, citations and limitations.
- `tests/test_r3a3g_m12.py`: 13 focused tests covering planning, exact admission, ten-entry extraction and deduplication, dates, conflicts, no-evidence, comparison, follow-up, feedback, API scope/auth and the PUKE client.
- `tools/r3a3g_m12_demo.py`: reproducible evidence producer.

### Christmas markets result

Source: `https://www.visitbritain.com/en/things-to-do/christmas-markets-britain` (VisitBritain, fetched live).

Pulse Search extracted ten distinct markets and preserved the publisher's feature order:

1. Newcastle Christmas Market — 19–23 December 2026
2. Frankfurt Christmas Market, Birmingham — 5 November–24 December 2026
3. Edinburgh Christmas Markets — 14 November 2026–3 January 2027
4. Manchester Christmas Markets — 6 November–22 December 2026
5. Cardiff Christmas Market — 12 November–23 December 2026
6. York Christmas Market — 12 November–21 December 2026
7. Bath Christmas Market — 26 November–13 December 2026
8. Bristol Christmas Market — November–December 2026 (month-level only)
9. Glasgow Christmas Market — no 2026 date extracted; unconfirmed
10. Hyde Park Winter Wonderland — 19 November 2026–3 January 2027

The output explicitly says the order is the cited publisher's feature order, not an independent ranking. It does not claim the two month-level entries have confirmed exact dates.

## Safeguards preserved

- Exact canonical source admission only; provider output alone never becomes evidence.
- Existing SSRF/DNS protections, redirect checks, robots checks and bounded fetches are reused.
- No unrestricted crawl, local indexing, production deployment, paid API or public Wiki publication was performed.
- No Wiki proposal was created or published; M12 keeps the existing draft-only pathway.
- Crawler safety PR #10 was not merged or activated.
- Full page text is retained only in memory for the request; output carries short excerpts, dates and citations.
- Provider leads are labelled `unverified_provider_lead`; approved pages are labelled `approved_source`; official outbound links are labelled `official_link`.
- API access remains bearer-token protected and loopback-bind-only by default.

## Failures, limitations and outstanding approvals

1. **Live discovery degraded during the evidence run.** The local SearXNG container returned genuine live results initially (including VisitBritain for the Christmas query), but DuckDuckGo, Brave and Google CSE subsequently rate-limited or CAPTCHA-blocked the upstream engines. The saved demo therefore labels its discovery leads as `recorded_local_searxng_lead` and uses live retrieval for the pages. It must not be read as a fresh live-provider query. A durable SearXNG deployment needs non-throttled engines or an approved provider fallback.
2. Bristol has only a month-level 2026 span and Glasgow has no extracted 2026 date. Both are included as discoveries but marked unconfirmed rather than given invented dates.
3. The comparison is extractive; it does not compute journey times or rank markets.
4. The German answer is an English extract from an English official page; translation into German is not implemented.
5. The conflict case uses a clearly labelled `fixture.example` fixture because no live conflicting pair was found in the approved corpus.
6. Source rights and approval references are for this controlled demonstration only. Production source admission, retention periods and republication rights still require owner and legal review.
7. M12 does not add automatic model learning. Reviewed feedback produces advisory proposals; no ranking update is applied automatically.
8. Draft PR #11 remains draft and unmerged. Independent acceptance, provider reliability work, source-policy review and production approval remain outstanding.

## Reproduction

```bash
python -m unittest discover -s tests
python tools/r3a3g_m12_demo.py
```

Live API configuration requires a local SearXNG URL:

```bash
export PULSE_SEARXNG_URL=http://127.0.0.1:8888
export PULSE_API_TOKEN=local-test-token
python -m pulse_search_broad_r3a3g.api \
  --staging data/staging.sqlite \
  --sources config/m12_sources.json \
  --scopes health:read,research:read
```
